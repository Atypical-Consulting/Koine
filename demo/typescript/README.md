# TypeScript demo

A runnable, self-checking demo for Koine's **TypeScript emitter** target (issue #1073) — the
polyglot sibling of [`demo/Pizzeria.Domain`](../Pizzeria.Domain) (which proves the C# emitter
end-to-end as part of its own `dotnet build`).

## What it proves

1. `templates/starters/ordering` — a single `Ordering` context modeling an `Order` aggregate with
   an `OrderLine` value object and an `OrderStatus` state machine — regenerates cleanly to
   TypeScript with the Koine CLI.
2. The emitted TypeScript, plus a hand-written driver ([`src/main.ts`](src/main.ts)) that
   constructs and exercises it, type-checks under `tsc --strict` using the exact `tsconfig.json`
   the emitter ships to users.
3. The driver actually **runs** under Node and asserts real values:
   - `OrderLine.subtotal` is correctly derived (`unitPrice.multiply(quantity)`) for two different
     lines;
   - a freshly constructed `Order` defaults to `Draft` and carries both lines;
   - `Order` equality is by **id** (entity identity), not by structural contents — two orders with
     the same id but different lines/status are equal, and two orders with different ids are not;
   - the `Draft`, `Placed`, and `Shipped` `OrderStatus` values are all constructible, mutually
     distinguishable, and route correctly through the generated `OrderStatusMatch` exhaustive
     switch;
   - the generated `place()`/`ship()` mutators drive a legal `Draft -> Placed -> Shipped` walk, and
     calling `ship()` directly on a fresh `Draft` order (an illegal `Draft -> Shipped` transition)
     throws `DomainInvariantViolationError`, proving the `states status { ... }` block's runtime
     guard actually rejects illegal transitions.

   The driver asserts **values**, never emitted formatting/whitespace, so this demo never churns
   when the emitter's output shape changes — only when its *behavior* does.

## How to run it

```bash
bash demo/typescript/run.sh
# or, equivalently:
cd demo/typescript && npm run demo
```

`run.sh` is idempotent and callable from anywhere; it always:

1. regenerates `demo/typescript/generated/` from `templates/starters/ordering` with the Koine CLI;
2. type-checks `generated/` + `src/` under `tsc -p tsconfig.json` (`--strict`);
3. transpiles everything to `.build/` (git-ignored) and runs `src/main.ts` under `node`.

A clean run prints `TypeScript demo: all assertions passed.` and exits `0`. Any failed assertion
(or type/build error) exits non-zero with the offending detail on stderr.

### Toolchain requirement

This demo needs `tsc` (TypeScript) and `node` on `PATH` — or the `KOINE_TSC` / `KOINE_NODE`
environment variable overrides, exactly as the `tests/Koine.Compiler.Tests/Conformance/` suites
honor. When neither is available, `run.sh` prints an install notice and exits `3` (the toolchain-absent
sentinel `tests/Koine.Compiler.Tests/DemoBuildTests.cs` maps to a clean, honest xUnit **Skipped** result
locally, and a hard **Failed** under `KOINE_REQUIRE_CONFORMANCE=true` — the flag CI sets, so a
toolchain that silently goes missing in CI reddens the build instead of hiding as a skip). No npm
`node_modules` install is required: the demo relies only on a global `tsc`/`node`, the same way the
conformance harness does.

## Layout

```
demo/typescript/
  package.json       "type": "module", npm run demo -> bash run.sh
  tsconfig.json       strict, moduleResolution "bundler" (editor/IDE support; run.sh drives tsc directly)
  run.sh               generate -> gate -> type-check -> transpile -> run -> assert
  src/main.ts          the hand-written driver (see above)
  generated/           git-ignored; regenerated by every run.sh
  .build/              git-ignored; transpiled JS + the ESM extension-resolution loader
  reference/           one or two committed emitted .ts snapshots, for browsing without running the tool
```
